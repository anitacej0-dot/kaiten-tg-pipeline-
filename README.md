# Kaiten TG · конвейер постов канала @kaiten_ru

Репозиторий-конвейер для канала [@kaiten_ru](https://t.me/kaiten_ru): обновление продукта
на входе, готовый пост с иллюстрациями и обоснованием на выходе, факт после публикации
на входе следующего поста.

**Два принципа.** Продуктовое утверждение идёт в пост только из базы знаний Кайтена,
дословно. Правило, которое расходится с реальными постами канала, чинится само,
а не текст под него.

## Точка входа

```
/post <тема или ссылка на статью базы знаний>
```

Скилл `.claude/skills/post/SKILL.md` ведёт агента по [docs/RUNBOOK.md](docs/RUNBOOK.md):
тип → фактура из базы знаний → угол → **гейт** → 2-3 варианта → валидатор → редакционная
проверка → рекомендация → **гейт** → иллюстрации → предсказание → публикация → факт.

**Два согласования с человеком:** (1) тип, фактура и угол до генерации,
(2) финальный текст до публикации.

## Четыре типа постов

Выведены разбором 11 дословных постов канала, длины посчитаны по реальным текстам.
У обновления две карусели на выбор: «что изменилось» (карточки изменений, счётчик `N / N`)
и «как сделать» (карточки шагов). «Как сделать» это вариант карусели, а не отдельный тип.

| Тип | Длина | Просмотры | Реакции | Иллюстрации |
|---|---|---|---|---|
| **Дайджест обновлений** | 880-1950 | 637-957 | 7-18 | декоративная обложка + карусель |
| **Обновление и фича** | 750-1550 | 758-1350 | 16-30 | обложка со скриншотом + карусель со счётчиком |
| **Кейс и статья** | 820-1050 | 787-928 | 9-26 | карусель |

Анатомия каждого типа со скелетами - [docs/POST-TYPES.md](docs/POST-TYPES.md).

## Скрипты

```bash
python scripts/validate-post.py content/posts/<slug>/post.md   # проверка текста
python scripts/validate-post.py content/posts/<slug>/post.md --type=дайджест
python scripts/extract-variant.py content/posts/<slug>/post.md 1  # текст к публикации
python scripts/check-facts.py                                  # долги по факту
python scripts/render-images.py content/posts/<slug>/img/*.html   # HTML → PNG 2×
node scripts/render-images.mjs content/posts/<slug>/img/*.html    # то же на Node
```

Валидатор ловит букву «ё», запрещённую лексику («функционал», «для того чтобы», «фича»),
оценочные усилители, нейро-шлак, неверное позиционирование продукта, дефис вместо
длинного тире, «Вы» с прописной, точку в заголовке, обязательные элементы типа поста
и клонов внутри набора. Любой FAIL правится до нуля.

**Регрессия:** валидатор прогнан по реальным постам канала. Он их пропускает и ловит
ровно одно настоящее нарушение редполитики - «функционал» в посте #1487.

## Первый запуск

```bash
git clone https://github.com/anitacej0-dot/kaiten-tg-pipeline-.git
cd kaiten-tg-pipeline-
```

```bash
python --version        # нужен Python 3.10+
node --version          # опционально, для render-images.mjs
```

Ставить через npm ничего не нужно. Рендер картинок работает на headless Chrome:
`scripts/render-images.py` находит его сам, Node не требуется.

## Правило редакции, о котором забывают

**Буквы «ё» нет нигде: ни в тексте поста, ни на иллюстрациях.** Всегда «е».
Валидатор проверяет текст, макеты проверяются глазами на шаге 10.

## Чего здесь нет

Скоринг это рубрика для рассуждения, а не ML-модель. Пока по постам конвейера не набран
факт, баллы это структурированное мнение. Именно поэтому шаг 11 (факт T+24 и T+72)
обязательный, а предсказания задним числом не переписываются.

Прежняя версия репозитория была собрана из инфлюенс-конвейера и мерила рекламный креатив
для закупки в чужом канале: нативность против рекламы, оффер, лендинг, жанровое
разнообразие сета из пяти текстов. Для своего канала это не подходит, и от этого
наследия репозиторий очищен.
