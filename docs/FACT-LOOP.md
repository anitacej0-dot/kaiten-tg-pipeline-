# Петля факта: что меряем, когда и что с этим делаем

> Скоринг без факта - вкусовщина с лишними шагами. Поэтому у каждого опубликованного
> поста есть **долг по факту**, и он проверяется скриптом:
>
> ```
> python scripts/check-facts.py
> ```
>
> Прогонять в начале рабочего дня и перед стартом нового поста.

## 1 · Метрики своего канала

За охват в своём канале деньги не платятся, поэтому метрики не рекламные:
меряем не стоимость контакта, а пользу и намерение.

| Метрика | Как считать | Что означает |
|---|---|---|
| **Просмотры** | из Телеграма на T+24 и T+72 | размер волны, сильно зависит от времени выхода |
| **ER** | (реакции + комментарии) / просмотры | зацепило или пролистали |
| **Пересылки на 1000 просмотров** | пересылки / просмотры × 1000 | **главная метрика пользы**: пост отправили коллеге |
| **CTR** | клики по UTM / просмотры | намерение пойти дальше |
| **Регистрации** | из аналитики по `utm_content` | конверсия, копится долго, смотреть помесячно |
| **Отписки за сутки** | из статистики канала | цена ошибки, ловит перегрев анонсами |

**Медиана считается по типу поста, а не по каналу целиком.** Дайджест собирает
просмотры при малом числе реакций, обновление наоборот. Сравнивать их между собой
бессмысленно, диапазоны по типам - в [POST-TYPES.md](POST-TYPES.md).

## 2 · Ритуал

1. **T+24ч** - просмотры, реакции, пересылки, комментарии, отписки за сутки.
2. **T+72ч** - то же плюс клики по UTM и регистрации → поля `facts` в `ab-plan.json` поста.
3. **Калибровка** - сверить факт с предсказанием, которое лежит в том же файле:
   какие гипотезы сошлись, какие нет → правка персон, голос-профиля, весов линз.
   Вердикт пишется в `calibration`. **Предсказания задним числом не переписываются.**
4. **Уроки** - три строки в `lessons`: что сработало, что нет, что меняем в следующем посте.

## 3 · Формат ab-plan.json

```json
{
  "post": "2026-09-01-zavershennye-iteracii",
  "type": "обновление",
  "utm_source": "tg",
  "utm_medium": "social",
  "utm_campaign": "0109",
  "utm_content": "2026-09-01-zavershennye-iteracii-v1",
  "published_at": "2026-09-01T18:00:00+03:00",
  "predictions": {
    "per100": { "проскроллят": 62, "дочитают": 24, "отреагируют": 9, "перешлют": 3, "кликнут": 4 },
    "target_personas": ["действующий пользователь", "руководитель команды"],
    "hypotheses": [
      "пересылки выше медианы типа: пост пересылают команде как аргумент на ретро",
      "клики выше медианы: ссылка ведёт в инструкцию, а не на лендинг"
    ],
    "risks": ["тема узкая, часть аудитории пролистает"]
  },
  "facts": {
    "t24":  { "views": null, "reactions": null, "forwards": null, "comments": null, "unsubs": null },
    "t72":  { "views": null, "reactions": null, "forwards": null, "clicks": null, "signups": null }
  },
  "calibration": null,
  "lessons": []
}
```

`predictions` заполняется **до публикации**, `facts` - после, `calibration` и `lessons` -
на шаге 3 ритуала. Пустые `facts` при заполненном `published_at` это и есть долг,
который ищет `check-facts.py`.

## 4 · Что калибруется по факту

| Расхождение | Что правим |
|---|---|
| Пересылок сильно меньше прогноза | портрет персоны: мы ошиблись в том, что для неё ценно |
| Реакций много, кликов нет | пост-развлечение: усилить связку «польза → следующий шаг» |
| Просмотры ниже медианы типа | слот публикации или первая строка, а не текст целиком |
| Отписки выше обычного | проверить, сколько анонсов было подряд (правило одного из трёх) |
| Победитель по баллам проиграл фактом | веса линз или сама рубрика проверки |

Отдельно копится статистика **по типам первой строки**: CTR поста приписывается тому,
как открывается пост (заголовок с датами, вопрос, название функции, имя компании).
Через 10-15 постов видно, какие открытия реально кликают в этом канале, и это уже
не гипотеза. Паттерны первых строк по типам - в [POST-TYPES.md](POST-TYPES.md).

## 5 · Когда гипотезы заменяются числами

Ориентиры взяты из корпуса 11 дословных постов, снятого 03.09.2026: дайджест 637-957
просмотров и 7-18 реакций, обновление и фича 758-1350 и 16-30, кейс 787-928 и 9-26.
Это **наблюдение за один заход**, без учёта сезона и роста канала. После 10 постов,
проведённых через конвейер, медианы по типам считаются по своим данным и заменяют
эти цифры прямо в этом файле, с датой пересчёта.

До этого момента любой балл скоринга читается как структурированное мнение,
а не как измерение. Так и говорить человеку.
