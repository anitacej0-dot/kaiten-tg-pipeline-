# Конвейер постов канала @kaiten_ru

Полная спека - `docs/RUNBOOK.md`. **Создай задачи на каждый шаг и иди по порядку.
Гейты не пропускай.**

## Иерархия источников

Читать в этом порядке, при расхождении верхний главнее:

1. **`references/editorial-policy.md`** - редполитика Kaiten: язык, лексика, тон,
   типографика. Источник истины - репозиторий `kaiten-article-pipeline/knowledge`.
2. **`docs/POST-TYPES.md`** - анатомия четырёх типов постов, скелеты, длины.
3. **`references/voice-profile.md`** - как канал звучит и выглядит поверх редполитики.
4. **`references/real-posts.md`** - корпус из 11 дословных постов. **Если правило
   расходится с корпусом, правило неверно и правится оно, а не пост.**

## Шаг 0 - долги по факту
```
python scripts/check-facts.py
```
Есть долги - сначала закрыть. Если пользователь спрашивает «как дела с каналом»,
начинать тоже отсюда.

## Шаг 1 - тип и папка
Определить тип: **дайджест · обновление и фича · кейс и статья · как сделать**.
Завести `content/posts/<YYYY-MM-DD>-<slug>/` с `post.md` и `ab-plan.json`.
Свериться с `content/plan.md` на антиповторы.

## Шаг 2 - фактура ⛔ гейт качества
**Единственный источник продуктовых утверждений - база знаний `faq-ru.kaiten.site`.**
Выписать дословно: названия вкладок, кнопок, полей, порядок действий, ограничения
(тариф, модуль, версия серверной поставки, бета), даты отключения старого.

Отдельным списком записать **«чего на странице нет»**. Чего в статье нет, того нет
в посте. Утверждение без источника не идёт в пост.

Для кейса: согласие героя на имя и должность, цифры масштаба, ссылка на материал.

## Шаг 3 - угол и роль
Роль и боль дословно из `references/icp-kaiten.md`. Что читатель сможет после поста,
чего не мог до. Дать 1-3 варианта угла.

## Шаг 4 - ⛔ ГЕЙТ: согласование типа, фактуры и угла
Человек выбирает или правит. Генерация только после «ок».

## Шаг 5 - текст
2-3 варианта **внутри одного типа**: разный заход, длина, концовка. Скелет типа
из `POST-TYPES.md` соблюдать. Тексты в блоки:

````
## Вариант 1 · обновление
```post
<текст>
```
````
Название типа в заголовке обязательно, по нему валидатор включает проверки.

## Шаг 6 - ⛔ ВАЛИДАТОР (автономно)
```
python scripts/validate-post.py content/posts/<slug>/post.md
```
Любой FAIL правится, гоняем снова до нуля. Ловит букву «ё», запрещённую лексику,
оценочные усилители, нейро-шлак, позиционирование, тире, обязательные элементы типа.

⚠️ Ругается на текст, который человек правил руками, - не перезаписывать молча,
показать нарушения и спросить.

Рассуждением, а не скриптом: подтверждён ли каждый FACT базой знаний, совпадают ли
названия кнопок дословно, пассив, инверсия, польза каждого абзаца, ICP-сверка.

## Шаг 7 - редакционная проверка
По `docs/SCORING.md`: разметка FACT/INFERENCE/RISK → integrity-гейт → 6 линз →
composite и зона → панель персон → adversarial → правки P0/P1.
Отчёт в `content/posts/<slug>/scoring/`.

## Шаг 8 - рекомендация
Какой вариант ставим и почему: не «победитель по баллам», а место в плане недели.

## Шаг 9 - ⛔ ГЕЙТ: согласование финального текста
Человек читает победителя с P0 и говорит «ок» или правит.

## Шаг 10 - иллюстрации и предсказание
Формат по типу поста из `docs/VISUALS.md`: обложка, карусель, видео.
Число карточек обязано совпасть с числом, обещанным в тексте.

```
python scripts/render-images.py content/posts/<slug>/img/*.html
```

**Посмотреть PNG глазами:** нет буквы «ё», бренд латиницей `Kaiten`, конфиденциальное
заблюрено, скриншот читается без увеличения.

Заполнить `ab-plan.json` ДО публикации. UTM канала:
`utm_source=tg&utm_medium=social&utm_campaign=<ДДММ>`.

## Шаг 11 - публикация и факт
`published_at` → ритуал `docs/FACT-LOOP.md` T+24 и T+72 → калибровка → уроки.
Предсказания задним числом не переписываются. Обновить `content/plan.md`.
Новый приём оформления - дописать в `references/real-posts.md`.

## Definition of Done
Долги закрыты · тип выбран · фактура из базы знаний со списком «чего нет» · угол
согласован · текст по скелету типа · **валидатор = 0** · редакционная проверка ·
рекомендация · финальный текст согласован · иллюстрации отрендерены и просмотрены ·
ab-plan заполнен ДО публикации · план обновлён · после выхода факт и калибровка.

## Полезное
- Не хватает шага - дописать скрипт и ранбук, а не импровизировать разово.
- Расхождение правила с корпусом чинится в правиле. Решение записывать в тот файл,
  где живёт правило, со ссылкой на пост-контрпример.
